# 页面数据导出与策略执行器

`tools/ilovecat-workbench.user.js` 是一个无第三方依赖的篡改猴用户脚本。模拟器本身仍然完全离线，不会加载该脚本或访问游戏接口。

## 安装

1. 在 Tampermonkey 中新建脚本，粘贴 `tools/ilovecat-workbench.user.js` 的完整内容并保存。
2. 打开 `https://api.ilovecat520.me/playground/battle`，确认右上角出现猫咪按钮。
3. 首次使用“导出数据”并选择战斗逻辑 JS 前，至少进入过一次战斗界面，让浏览器加载当前版本的战斗代码。导出时不必正在战斗。

当前 `main` 分支的安装地址：

```text
https://raw.githubusercontent.com/ZeroJehovah/ilovecat-battle-sim/main/tools/ilovecat-workbench.user.js
```

顶部把原“执行策略”拆为“在线策略”和“本地策略”两个页签。在线页从私有 docs 仓库的 strategies/index.json 读取策略，刷新图标与关卡标签排在同一行；每次只列出一个关卡的策略。未选中策略只显示标题与标签，选中后才展开按 C/B/A/S 排序、按等级着色的配队和说明。本地页只允许选择 JSON 文件。自动开始战斗和自动倍速默认勾选，自动开战只在用户点“开始执行”后触发。

0.5.1 精简在线策略页头部，改用 Lucide `refresh-cw` 开源 SVG 图标（ISC 许可），并统一配队排序与等级着色，移除重复的来源和选中提示。自动开始战斗、自动倍速默认勾选。

0.5.0 拆分在线/本地入口，增加在线策略的关卡标签筛选和选中项展开详情。在线与本地策略都在选定后自动校验，不再提供“校验”按钮；索引、配队、等级或关卡不一致时仍会拒绝执行。

面板标题后会显示当前版本号；脚本声明了 `@updateURL` 和 `@downloadURL`，Tampermonkey 可以直接检查 GitHub `main` 分支更新。`0.3.10` 将固定关卡的父复选框从整行 label 中拆出，避免鼠标悬停关卡 id 输入框时触发复选框高亮。`0.3.9` 将每日任务、固定关卡和 JS 源码改为由后续选择或输入自动勾选父项；清空后续内容会自动取消父项，手动取消父项会清空其后续内容，父项本身不能用鼠标或键盘直接勾选。`0.3.8` 重新对齐导出页的复选框与中文文字，统一各行高度，将固定关卡输入框增高到 30px，并移除“JS源码”后的冒号。`0.3.7` 将校验结果中的“成功”“警告”“错误”文字标记移除，仅保留绿、黄、红三种字体颜色用于区分状态。

脚本匹配游戏域名下的页面，但只有点击猫咪按钮后才读取数据。导出请求与普通页面请求使用同一登录态；脚本不会展示、复制或上传 UID、Cookie 或请求头。

## 在线策略索引

在线策略来自私有 docs 仓库中的 strategies/index.json。执行器使用 Tampermonkey 的 GM_xmlhttpRequest 读取固定索引地址，因此需要当前浏览器已登录有权限访问该私有仓库的 GitHub 账号；匿名访问 private raw 会返回 404。策略列表先按索引里的 stage.id 去重生成关卡标签，默认选择第一个关卡，并且只渲染当前标签下的有效条目。刷新按钮位于关卡标签行最前方。

索引记录当前等级基准和每个策略的标题、描述、关卡、配队、文件与 raw 地址。脚本选定条目后还会下载对应 JSON，并核对 format/version、stageId、猫咪集合和等级；索引或文件发生变化时会拒绝载入并提示刷新，而不是继续执行过期策略。在线读取只发送 GET 请求，不携带游戏账号信息。

## 按范围导出

“复制所选 JSON”和“下载所选 JSON”共用同一组勾选项。所有导出项默认不勾选，刷新页面后重置；按需选择图鉴、账号信息、页面活动关卡、固定关卡或 JS 正文。

可选范围：

- `图鉴基础数据`：`catalog.cats`、`catalog.mice`、`catalog.items` 和 `catalog.rules`，默认关闭；
- `已拥有猫咪的等级列表`：导出 `roster.ownedUnits`，属于账号相关数据，默认关闭；
- `当前无尽`、`每日任务` 和 `限时活动`：单独显示关卡类型和名称，分别勾选；每个选中关卡都保留完整 `waves`。每日任务的四档难度收在同一行，即使父项未勾选也可以选择难度；选中任一难度会自动勾选“每日任务”，四档全部取消则自动取消父项。手动取消父项会清空四档难度选择。四档难度来自 `/state.daily.choices`，即使当日已经通关或领奖也仍会列入；导出的只是公开关卡正文，不包含 `chosen`、`won` 等账号状态。限时头目来自 `/api/cat/battle/raid`，不属于 `/catalog` 的固定关卡或 `/endless`；
- `固定关卡`：直接在输入框中填写逗号分隔的关卡 id（例如 `1,2,3`），有输入时自动勾选父项，清空输入后自动取消；手动取消父项会清空输入。父项本身不能手动勾选。只导出输入且当前页面仍存在的普通关卡；
- `JS源码`：直接选择“战斗逻辑”或“全部”，选择后自动勾选父项；手动取消父项会清除单选状态。父项本身不能手动勾选。选择“战斗逻辑”会写入识别出的战斗 bundle 正文、大小、URL 和 SHA-256；“全部”还会把当前页面加载过的每个同源 `.js` 文件完整正文写入 `client.allScripts`。

战斗逻辑 JS 是游戏当前版本的战斗代码，不是一场战斗的实时状态或回放记录。脚本从当前标签页已经加载的同源脚本中按战斗引擎特征识别 bundle，因此不需要在点击导出时正在战斗；但首次打开或刷新页面后，通常要先进入一次战斗界面，让浏览器加载这个 bundle。若识别失败，脚本会提示先进入一次战斗界面。

JS 选项“全部”不是运行日志，也不是只需计算的索引，而是浏览器当前已经请求过的同源 JavaScript 源码副本。它通常有数 MiB，只有需要离线审查其他页面模块或补丁时才选；单纯分析猫、鼠、关卡和波次时保持默认即可。

导出结果的 `selection` 会记录本次勾选；`snapshot` 只包含所选图鉴字段和所选关卡，`roster` 只在勾选已拥有猫咪时出现，`client` 只在选择战斗逻辑 JS 时出现。顶层 JSON 不再包含 `privacy` 说明字段。

## 提取模拟器快照

所选 JSON 的 `snapshot` 字段就是可放到模拟器 `data/snapshot.json` 的顶层结构，包括 `schemaVersion`、`capturedAt`、`source`、所选 `catalog` 字段和所选关卡；它不包含账号信息或 JS。界面不再单独生成快照文件，避免维护两个数据相同的下载入口。

使用 `jq` 时可以直接提取：

```bash
jq '.snapshot' ilovecat-export-YYYYMMDD-HHMMSS.json > snapshot.json
```

- 必须勾选“图鉴基础数据”和至少 1 个关卡；
- 选择普通关卡、每日任务或限时全服头目时，所选关卡进入 `catalog.stages`；如果没有选择当前无尽关卡，优先把当前选中的每日难度、其次把限时头目、最后把第一个所选普通关卡写入 `stage`，让快照可以直接运行；
- 选择当前无尽关卡时，它写入 `stage` 和 `endlessMeta`；同时选择的其他非无尽关卡进入 `catalog.stages`；
- 选择每日任务时，选中的每种难度都保留完整波次；`snapshot` 不写每日选择档位或领奖状态；
- 选择限时全服头目时，还会写入公开的 `raidMeta`（活动 id、起止日期和运行状态）；活动已结束时不再列入可选关卡；
- 快照只覆盖本次选择。未勾选的关卡不会出现在替换后的快照中，依赖这些关卡ID的场景也会明确报错。

导出明确排除 UID、Cookie、授权头、罐罐余额、通关数、星级、抽卡统计、保底计数、无尽次数、最佳成绩，以及每日任务的选择档位和领奖状态。

## 策略格式

策略必须是一个 JSON 对象：

```json
{
  "format": "ilovecat-battle-strategy",
  "version": 1,
  "name": "candidate",
  "stageId": 9101,
  "team": [
    { "id": "s4", "level": 1 },
    { "id": "s1", "level": 1 }
  ],
  "items": ["fast_coins", "rally"],
  "policy": {
    "walletTarget": 8,
    "economyFirst": true,
    "openers": [],
    "deploySequence": ["s4", "s1", "s1"],
    "targetCounts": { "s4": 3, "s1": 10 },
    "priority": ["s4", "s1"],
    "fallbackAfter": 775,
    "fallbackPriority": [],
    "autoCannon": true,
    "automatic": true,
    "strictTimeline": false,
    "timelineTolerance": 0.25,
    "actions": []
  }
}
```

`policy` 的自动决策与模拟器场景保持一致：

- 钱包低于目标时，先完成尚未成功的 `openers`，再在金币足够时升级钱包；
- `economyFirst=true` 时，等待钱包达标后才铺正常阵容；
- `deploySequence` 是钱包达标后严格执行的上场顺序，允许重复 id；下一只金币不足或槽位冷却时原地等待，不会改买 `priority` 或其他便宜猫；等待期间仍可发射已充能的猫爪炮；序列完成后才进入目标存活数维护；
- 钱包达标后，按 `priority` 检查目标存活数，槽位冷却时跳过并检查下一只；
- 到达 `fallbackAfter` 后，在目标无法补位时使用 `fallbackPriority` 填场；
- 自动猫爪炮只会在没有更高优先级操作时发射。

`actions` 可覆盖自动决定，支持 `deploy`、`wallet`、`cannon` 和 `wait`：

```json
[
  { "at": 0, "type": "deploy", "id": "s4" },
  { "at": 30, "type": "cannon" },
  { "at": 45, "type": "wallet" }
]
```

`strictTimeline=true` 表示动作表是精确回放。超过 `timelineTolerance`（默认 0.25 秒）仍未成功就停止，避免时间轴悄悄漂移。

## 执行方式

1. 把策略 `team` 里的猫都放进编队即可，顺序不强制。额外槽位可以放不参与部署的猫；策略猫位于第 2 页时，执行器直接按 `6–9`/`0` 部署，不切换页面。
2. 在线页先选择关卡标签，再从当前关卡列表中选策略；本地页选择 JSON 文件。两种入口都在选定后自动校验，没有单独的校验按钮。策略名称、适用关卡和策略配队固定显示在信息区；配队使用“猫咪名称(等级)”格式，并按 C/B/A/S 评级使用不同颜色。已经在战斗中时，脚本核对实时关卡、队伍、等级和道具；停留在“出战”准备界面时，脚本核对关卡 id、所需猫是否存在、道具库存和勾选状态。
3. 如果策略 `items` 非空，准备界面会出现醒目的消耗品提示。执行器开始前会按策略自动勾选或取消消耗品；库存不足或准备界面缺少该道具时会拒绝开战。该行为不提供关闭选项。
4. “自动开始战斗”和“自动倍速”默认勾选。已经在战斗中时点“开始执行”；如果还没有战斗，脚本会点击准备界面的“开始战斗”（消耗 1 次挑战），等待匹配关卡的新战斗快照出现后立即执行第一轮操作。如不希望自动开始战斗，可先取消勾选。
5. 自动开战只在准备界面关卡匹配、所需猫全部在编队、道具选择匹配时点击；任何一项不一致都会拒绝开战。脚本优先从 React 准备弹窗读取真实 `stage.id` 与策略 `stageId` 比对，读不到 id 时才退回标题/名称比对；例如在“第 1 关”准备界面执行 `stageId: 9001` 的策略会直接报错并保持弹窗。脚本不会调整队伍、购买升级或选择服务器种子。
6. 战斗状态会显示当前倍速。动作节流按真实时间计算，`2×`/`3×` 会放大两次操作之间的游戏时间；追求逐帧复刻时建议保持 `1×`，脚本会在非 `1×` 时显示提示。“自动倍速”默认勾选，脚本只在长空闲段切到 3×，并在动作前切回 1×；详见下一节。
7. 战斗结束、页面暂停、提示层出现或快照消失时，脚本停止或等待，不会自动重开战斗。

脚本空闲时约每 100 ms 检查一次 React 战斗快照；一次动作成功后，不再等下一个 100 ms 轮询，而是用 `setTimeout` 在 250 ms 边界精确唤醒下一次动作，典型额外延迟只剩事件循环和渲染的几毫秒。自动开战把“人工点开始、再切回工具点执行”的秒级空窗压缩到一次页面请求和首次渲染的延迟；固定关卡实测能在 `t=0.00s` 读到新战斗快照，但游戏快照本身约 100 ms 更新一次，世界王仍可能受网络和页面卡顿影响，不能保证逐帧一致。模拟器用 `policy.observationDelay: 0.1` 表示这层约 10 Hz 的视野延迟；它和 `actionGap: 0.25` 一起用于离线统计。

## 自动倍速

勾选“自动倍速”后：

- 执行器根据策略、当前金币、钱包等级、槽位冷却、猫爪炮充能和最近约 3 个游戏秒的实际金币收入，估计下一次可能操作的时刻；
- 只有预计至少约 9 个游戏秒没有操作时才切到 3×；下一次操作进入约 5 个游戏秒窗口时切回 1×。如果最近有击杀金币入账，退出窗口会按额外收入自动放大，最多约 11 秒，进入窗口相应最多约 15 秒；
- 倍速按钮的点击也遵守 250 ms 页面操作间隔；
- 自动倍速开启时，只要确认到的倍速不是 1×，执行器就不会执行任何部署、钱包或猫爪炮动作；切回 1× 并确认后才继续；
- 使用自动开战时，会在点击“开始战斗”前把游戏保存的 `snowapi-cat-battle-speed` 设为 1，保证新战斗从 1× 开始；已经在战斗中启动时，会先把 2×/3× 切回 1×；
- 停止执行或取消勾选时，如果倍速是执行器升上去的，会尝试切回 1×，并把保存倍速写成 1；
- 状态栏显示当前倍速、自动目标（空闲 3× / 动作前 1×）和估计的下次操作时间。

估计基于延迟快照和最近收入，击杀金币可能让下一次操作比估计更早。发生这种情况时执行器会先切回 1× 再操作；最坏会多等一个约 250 ms 的动作间隔，但不会在 2×/3× 下执行策略动作。自动倍速只压缩真实等待时间，不改变模拟器里的游戏内决策时间轴。

## 准备界面拦截规则

| 检查项 | 结果 |
| --- | --- |
| 准备界面 `stage.id` 与策略 `stageId` 不同 | 错误，拒绝开战 |
| 读不到 `stage.id` 且标题/名称都不匹配 | 错误，拒绝开战 |
| 编队缺少策略 `team` 中的猫 | 错误，拒绝开战 |
| 编队顺序与策略不同 | 仅提示，不拦截 |
| 策略猫在编队第 2 页 | 不拦截；执行器用 `6–0` 直接部署 |
| 编队有额外槽位 | 仅提示，不会被策略主动部署 |
| 策略 `items` 非空 | 橙色提示本局会消耗的消耗品 |
| 道具未勾选/多选/库存不足 | 错误，拒绝开战 |
| 策略 `items` 与准备界面勾选不一致 | 开始执行时按策略勾选/取消；库存不足时拒绝开战 |

编队顺序不影响猫的属性或部署决策：执行器按猫 id 查找实际槽位，并通过游戏自带的键盘映射部署——`1–5` 对应当前页，`6–9` 和 `0` 对应绝对槽位 5–9，因此后台页猫咪不需要换页。只有在当前页不是第 1 页、却要部署前五槽时，执行器才会先点一次“换页”回到第 1 页，避免数字键落到错误的猫上。

执行器的每次成功页面操作之间至少间隔 250 ms，并在到点后立即唤醒。模拟器的 `policy.actionGap` 使用同一约束；世界王和无尽策略都已写入 `actionGap: 0.25` 与 `observationDelay: 0.1`，离线统计也按这两个约束重跑。

执行器依赖游戏当前页面的 React 内部快照和按钮标题。游戏大版本更新后，如果校验或快照读取失败，应重新核对战斗 bundle 和页面 DOM，不应盲点继续执行。若自动开战后 20 秒内没有出现匹配的战斗快照，执行器会停止并提示检查页面错误。

## 边界

- 服务器种子不可选择；策略只能缩小决策误差，不能保证达到某个离线种子成绩。
- 执行器不能补回脚本启动前已经错过的操作，也不能消除浏览器帧率、网络和人工准备造成的差异；自动开战只能缩小开战空窗。
- 执行器不会选择队伍或购买升级；勾选“自动开始战斗”时只会点击准备界面的“开始战斗”，并消耗 1 次挑战。执行器开始前会按策略勾选准备界面的道具复选框，实际扣除以服务器开战请求为准。
- 执行器只读 React 战斗快照，不读取 `abilityTimer`，不能保证时空旅喵的技能相位与回放轨迹一致。
- 页面工具不会修改模拟器文件；导出后仍需人工审阅并保存到合适位置。
